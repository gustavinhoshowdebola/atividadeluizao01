1. Qual foi a principal vantagem de utilizar branches?
A principal vantagem foi permitir que cada integrante trabalhasse em uma funcionalidade ou alteração sem interferir diretamente no código principal. Isso facilitou a organização e reduziu o risco de erros no projeto.

2. Por que os Pull Requests são importantes em projetos colaborativos?
O Pull Request permite revisar as alterações antes de incorporá-las ao projeto principal. Assim, a equipe pode discutir o código, identificar possíveis problemas e garantir uma melhor qualidade do trabalho.

3. Como acontece um conflito de merge?
Um conflito de merge acontece quando duas branches modificam a mesma parte de um arquivo de maneiras diferentes. O Git não consegue decidir automaticamente qual alteração deve permanecer e solicita que os desenvolvedores resolvam o conflito.

4. Como a equipe resolveu o conflito encontrado?
Analisamos as alterações feitas em cada branch, conversou sobre qual versão deveria ser mantida e editou o arquivo para combinar as mudanças necessárias. Depois, o conflito foi marcado como resolvido, o código foi testado e as alterações foram adicionadas ao merge.

5. Qual prática de GitHub a equipe considera mais importante em projetos maiores?
Consideramos o uso de Pull Requests com revisão de código uma das práticas mais importantes. Em projetos maiores, essa prática ajuda a manter a qualidade, facilita a colaboração e evita que alterações problemáticas sejam adicionadas diretamente à branch principal.
